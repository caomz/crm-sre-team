# 2.3.1 修改摘要（2026-09-21）
## 已确认事实
validate_bundle 对影响报告的文件遍历显式排序，并对最终 checks/errors 作稳定排序；新增针对 validator 自身的 AST 排序检查。测试报告只去除 unittest 的实际耗时行中的耗时值，不隐藏测试名称、断言、失败或错误；原始直接运行输出另保存在发布日志。
保留原有测试函数与 helper，新增旧候选、旧请求和空 blocked 的兼容边界回归测试。新增具名矩阵及逐例机器报告，实际数量与结果见 [验证记录](VALIDATION.md)。矩阵不读取 Schema 的条件节点来生成预期结论；实际判定仍调用官方 jsonschema。
新增确定性集成检查，在临时副本中比较生成物、整棵发行树和验证输出；强制反转 Path 文件遍历、切换哈希种子，并注入未排序回归验证 AST 检查。新增源文件差异白名单检查，禁止 Schema/策略语义/提示词正文或既有测试变化。
构建器唯一逻辑改动为将新增 tests/*.py 纳入根锁，不改 ZIP_TIME、输出目录或压缩参数。policy-source、policies、注册元数据和 B/T 当前版本标记更新；原有 Schema、fixture、头像、ID、权限保持不变。所有生成物重新构建。

## 高概率候选
稳定输出与逐例预期能够提升第三方复核的可审计性；它们不增加 Harness 能力，也不证明序数推理有效。Schema 支持合法保守 direction，不能强制从 effect 反推唯一方向。

## 待验证
2.1.0 历史提到 settings.json（agent=telecom-crm-sre-team-lead），本包缺失，须对照原包；本次不创建。
workflows.json 任意阶段 early_handoff_event 与 roles.json 团长 HANDOFF 仅 P7 的契约缺口保持，不新增任务种类或授权。
包内外链未联网核验；author.email、展示描述、目标宿主注册/导入兼容性不擅自调整。
团长既有自检原文的极性矛盾及相邻判读补充原样保留，本次不改提示词判断行为。
Harness 为 NOT_IMPLEMENTED；B/T 全部 NOT_RUN_IN_TARGET_HOST。没有真实模型、原生 Windows、生产或宿主调用验证。

## 已排除
没有新增业务字段、扩大权限、删除原文件或重写历史测试结果。没有把空 blocked 视作漏洞，没有实现升级自动探测，也没有声称新的矩阵覆盖与历史大矩阵完全等价。

## 决策记录
采用 2.3.1 修订版，保持业务 Schema 字节与提示词正文（除版本标记）不变。
在计划的 effect、direction、reference、counterevidence 矩阵外，加入单独命名的混合支持/削弱矩阵，避免遗漏允许保守 direction 的场景；每个维度和数量均由脚本导出。
确定性集成测试单独运行，不加入 validate_bundle 内部 suite，避免递归；内部仍执行契约测试及具名矩阵。
历史 1024 组合记录保留在历史文档/机器报告，不作本次覆盖数，也不假定新的具名矩阵与其组合域相同。
在额外测试源进入发行包后，将 tests/*.py 纳入根锁；报告文件和运行耗时不进入完整性锁，避免动态产物自引用。
保留旧补丁，新增当前补丁并验证适用性；提示词补丁不是整包安装器。
发布 manifest 不写自己的哈希，避免自引用；它记录其余标准交付物的实际大小与 SHA256。
