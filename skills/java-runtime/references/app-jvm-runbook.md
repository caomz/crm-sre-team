# Java / JVM / WebLogic / Tomcat
领域资料基底：2.5.0。原生/兼容模式可按 Agent/Skill 的只读诊断与执行边界生成查询或观测命令，写明目标、范围、开销与未执行；本包不连接生产。生产写动作只给人工评审卡。托管模式仍遵守原契约，不生成生产命令。技术引用沿用原包，目标版本未在本次核验。
## 先用已有材料
确认现场是否Java及相关JDK、应用服务器版本，不假设一定是WebLogic或Tomcat。成员本次最多选 2 项，由宿主合并发布：故障窗口应用异常上下文、既有线程池/JDBC池指标、既有GC日志或进程退出记录。
线程池和连接池指标必须注明名字、active/idle/max/wait的定义、实例与采样时间；不同产品名称相近不等于语义相同。

## 第二轮分支
连接获取超时：核对等待池连接的请求、借出时间、池上限、数据库响应与长事务；不能直接认定Oracle达到sessions/processes限制。
CPU不高但慢：用线程等待对象和调用方向区分DB、HTTP、锁、池队列；RUNNABLE不等于一定在消耗CPU，线程栈单点也不能量化整体耗时。
GC：对齐暂停与受理时延，比较故障前后GC类型和暂停；单见Full GC不能宣布因果。确认JDK8旧格式与JDK9+统一日志差异，不能混用启动参数。
OOM：区分heap、metaspace、direct memory、native thread与宿主/容器OOM；先看退出记录和错误类型，再决定取证。
外围接口：沿同一匿名请求检查开始/超时/返回以及对端结果，区分慢调用和本地排队；不要盲目提高timeout或重试次数。

## 线程栈采集门禁
优先用户已有线程栈。缺失且确有区分价值时，先确认精确PID、进程启动时间、JDK工具兼容、同一授权用户、采集开销与本地输出空间。
线程栈 attach 仍仅作为人工评审后的采集需求：确认唯一目标、工具版本、授权、空间、开销和停止条件，不提供 attach 执行步骤；普通只读观测命令按下方边界生成。通常先评估一份既有栈；确需时间对照时再说明有限采样的区分价值。
原包引用的 JDK 文档将线程栈、堆直方图和堆转储列为不同开销，具体以目标版本为准。堆转储可能触发Full GC且暴露敏感内存内容，因此不作为常规第一轮取证。[JVM21]
诊断 attach 即使只读也至少按本包 R2 评估；只读观测命令可按只读边界生成，attach 本身只写评审卡。目标 JDK 兼容性未知时先保留缺口。
工具不可用或attach失败时，改收现有日志/监控，不改启动参数、不开远程JMX、不重启来方便采集。

## 禁止默认动作
不直接扩池、加堆、改GC、强制GC、调超时、重启全部实例。重启只能是人工评审后的缓解方案，不能当作根因结论；保存已有证据且不能延误现场必要止损。
