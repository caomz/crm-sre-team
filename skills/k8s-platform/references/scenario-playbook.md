# Workflow 与场景卡 · 2.5.0
所有场景共享 P0–P7，不另造阶段和配额；场景表是选材目录，不是要求一次全部上传。

| Workflow | 选择与共同输入 | 收敛与风险边界 |
|---|---|---|
| WF-A 重大故障 | 用户已有业务影响、时间窗、代表性材料；SEV 由组织定 | 应急提醒独立；日志不阻塞现场；恢复与 RCA 分开 |
| WF-B 变更后异常 | P1 和 P3 使用同一变更摘要、时间/对象与结果快照 | 相关不等于因果，保留关键替代解释，不二选一；回退仅人工评审卡 |
| WF-C 性能劣化 | 业务时延/成功、流量、资源与基线口径；按已有证据选域 | 拐点与变更重合时记录切到 WF-B 的理由，不确认变更致因 |
非事故任务以任务类型选择必要材料，不要求无关故障日志；不适用阶段须显式登记原因。

| 场景 | 首轮最少材料 | 关键区分 | 不得默认动作 |
|---|---|---|---|
| 登录/受理慢 | 时间与范围、代表性错误、一个成功率/时延摘要 | 本地排队/数据库/外围接口/渠道差异 | 重启所有应用 |
| JDBC取连接超时 | 池指标与定义、异常上下文、当前是否持续 | 连接被长期占用/DB慢/池上限/泄漏 | 直接扩池或终止数据库会话 |
| 订单/工单积压 | 状态分布/最老年龄、进出量、样本匿名链路 | 处理能力下降/回执缺失/业务拒绝 | 批量重推/改状态 |
| 夜间批次不结束 | 批次摘要、检查点、错误/依赖状态 | 上游未就绪/锁/资源争用/重复执行 | 全量重跑 |
| 主机load高CPU低 | 主机时间与核数、短采样或历史看板、相关业务影响 | IO/不可中断等待/采样错位 | 清缓存/重启 |
| 磁盘或归档告警 | 指定路径/空间趋势、对象类型、既有告警 | 空间/inode/挂载异常/归档依赖 | 删除归档/全盘扫描 |
| 发布后局部失败 | 变更摘要、影响实例与窗口、错误样本 | 配置/兼容/流量分布/其他事件 | 未评审直接全量回滚 |
| 容器重启 | 目标状态与lastState、相关时间、已有日志 | OOM/应用退出/探针/节点事件 | 删除工作负载 |
| 有备份但想核查可恢复 | 备份范围/摘要、恢复链、最近演练结果 | 作业成功/介质有效/端到端可恢复 | 在生产库试恢复 |
| 历史故障已恢复 | 历史窗口、既有日志/指标、人工动作时间线 | 真实历史证据/事后状态 | 用当前快照宣布历史根因 |

每个场景遵守首轮最多3项、按已给材料去重；表格只是选材依据。用户只给一个报错时，先解释该报错能够说明的范围，再选最有区分度的材料；成员只提出最多 2 项，用户实际请求由宿主统一发布。
