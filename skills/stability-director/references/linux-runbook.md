# Linux 与基础设施：小范围取证
版本：2.5.0。本文件只用于离线证据解读，所有新增生产采集或动作仅给人工评审卡，无可执行示例。技术引用沿用原包，目标版本未在本次核验。
## 第一轮
优先用户已有主机看板；成员只提出最多 2 项原子材料需求，由宿主合并后用户每轮最多 3 项。只选已确认受影响的一台代表性主机，标注匿名主机名、CPU核数、物理/虚拟/容器属性、时间及时区。未确认 Linux 时不作 Linux 特定判断。
没有历史采样时，当前采样不能用于证明历史故障原因。

## 人工证据评审卡目录（没有命令）
| 证据目的 | 优先已有材料 | 解释限制与人工评审点 |
|---|---|---|
| 时间基准 | 带原时区的采样时间 | 事件时间与采集时间分列 |
| 负载/CPU | 同窗主机摘要、核数与进程状态统计 | 核对首份累计报告与区间报告，不反推历史 |
| 内存 | 可用内存、交换活动与已有 OOM/退出记录 | 不能只看空闲值；宿主与容器限制分开 |
| 存储 IO | 指定设备吞吐、等待与队列摘要 | 保留版本、单位与表头，避免单值确认饱和 |
| 网络 | 既有双方超时/连接/解析错误摘要 | 统计不证明具体链路健康；不默认主动探测 |
新增现场采样也仅给卡片，写明授权对象、时窗、预算、开销、停止条件与替代资料；不输出任何生产命令。
vmstat / iostat 等现有采样需核对首份累计口径与后续区间口径，具体字段以目标版本资料为准。[VMSTAT][IOSTAT]

## 第二轮分支
CPU/Load：区分 runnable、不可中断等待、虚拟机 steal；有必要再由用户选择单PID或热点线程的短采样，不默认列全量进程启动参数。
内存：比较实际内存压力、swap活动、内核OOM与进程退出时间；不因 free 低就建议清缓存。容器限制和主机容量分别看。
I/O：结合 await、队列、吞吐与业务时间线，设备类型/多队列/SAN差异会影响解读；单一%util值不能直接定性为饱和。
空间：指定已知本地挂载点分别看容量和inode，排查增长来源和日志轮转；疑似NFS挂起时不做全盘扫描。
网络：先看已存在的超时/解析/连接错误和双方日志。主动ping、DNS查询、端口探测、抓包等另评估范围和权限，不能让AI执行；不默认抓全流量或改防火墙。
时间：日志错位先核实时区/时钟偏差；不建议在故障中直接改时间。

## 禁止默认建议
不要清缓存、清文件、重启网卡、防火墙改动、kill进程、内核调参来“试试看”。必要时仅提出 R3 人工评审卡，不给操作步骤。
卡顿或负载恶化时停止采集，不多开终端反复重试；必要时转现场主机/存储/网络支持。
